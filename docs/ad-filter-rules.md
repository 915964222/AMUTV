# 广告过滤规则（M3U8 切片级）

> 适用范围：点播 HLS（m3u8）播放链路。规则实现在 `ad-rules.js`，播放器（`js/player.js`）与服务端代理（`server.js`）共用同一份规则。
> 开关：设置 → 播放与搜索 →「M3U8 广告过滤」（默认开）。命中时会 toast 提示「已过滤 N 个广告切片」。

## 一、规则总览

过滤分三层，逐层执行，命中即剔除（连同该切片对应的 `#EXTINF` 行）：

| 层 | 规则 | 说明 |
|---|---|---|
| ① URL 关键词 | 见下方规则表 | 切片地址命中任一正则即判为广告。**相对路径会先解析成绝对地址再判一次**（采集站常写 `gg/promo.ts` 这种不带前导斜杠的地址，只查原文会漏） |
| ② HLS 标记 | `#EXT-X-CUE-OUT` ~ `#EXT-X-CUE-IN` | 标准 SCTE-35 广告插播区间，区间内切片整段丢弃（跑马灯/博彩贴片常借这个通道）；区间内的切片同样计入 `removed` 统计 |
| ② HLS 标记 | `#EXT-X-DISCONTINUITY` 包裹块 | 块内若存在广告切片，则整块（含标记）丢弃 |
| ③ 结构特征 | 少数派目录剔除 | 少量切片来自「另一个目录/另一个域名」——采集站插片的主流手法，见第三节 |

## 二、URL 关键词规则表

代码位置：`ad-rules.js` 的 `RULES` 数组（每项 `{ re, desc }`）。新增规则只需往数组里加一条，无需改动过滤逻辑。

### A. 通用广告目录 / 文件名

| 正则 | 命中示例 | 说明 |

| `/(^\|[\/\.\-_])ads?([\/\.\-_]\|$)/i` | `/ads/x.ts` | `ad`/`ads` 独立路径段 |
| `/advert/i` | `advertisement.ts` | 广告英文 |
| `/promot/i` | `promo1.ts` | 推广 |
| `/\/gg[0-9]*[\/\.]/i` | `/gg/`、`/gg2/` | 广告拼音目录 |
| `/guanggao/i` | `guanggao.ts` | 广告拼音 |
| `/\/yugao[\/\.]/i` | `/yugao/` | 预告引流 |

## 三、结构规则（少数派目录剔除）

采集站的广告不写在 URL 关键词里，而是**把广告 ts 从另一个目录/域名拼进正片播放列表**。实测样本：

| 源 | 广告切片特征 | 条数 |
|---|---|---|
| 360 | 主目录 `/20261012/dR8PCB3H/877kb/hls` 中夹入 `/20261008/2DExGZYA/hls/xxxx.ts` | 8 |
| 暴风 | 主目录外夹入 `/video/adjump/time/1787320...ts` | 9 |
| 量子 | 主目录外夹入 `/20261003/84_9109598f/2000k/hls/...` | 7 |

判定算法：

1. 把每个切片解析为绝对地址，取「协议 + 域名 + 目录」作为分组前缀；
2. 统计各分组条数，取条数最多的为主流组；
3. 若主流组占比 **≥ 60%**（`RULE_CONF.DOM_SHARE`），则占比 **≤ 8%**（`RULE_CONF.OUTLIER_SHARE`，且不少于 2 条）的少数派组判为广告，整组剔除；
4. 以下情况**不做判断**（防误杀）：
   - 切片数 < 20（`RULE_CONF.MIN_SEG`，样本不足）；
   - 主流组占比 < 60%（合法多 CDN 轮转，如公共测试流）；
   - 主播放列表（含 `#EXT-X-STREAM-INF`，其子流地址本就分散在不同目录）。

## 四、相对路径切片

播放列表里的切片地址有两种写法：

```
https://cdn.x.com/ad/1.ts     ← 绝对（规则直接命中）
gg/promo.ts                   ← 相对（多数规则带前导斜杠，只查原文会漏）
```

规则表里的 `/\/ad[\/_\-\.]/`、`/\/gg[0-9]*[\/\.]/` 等都以 `/` 开头，对相对路径不命中。因此 `filterM3U8` 对每个切片做两次判定：

1. 按原文查 `isAdUrl()`；
2. 若未命中且传入了播放列表地址，用 `new URL(uri, baseUrl)` 解析成绝对地址再查一次。

两次任一命中即判为广告（对外接口为 `AdFilter.isAdUri(uri, baseUrl)`）。实际影响：`gg/promo.ts` 这类插片现在能被识别，而正片相对路径（`v/0001.ts`）不会被误伤。

## 六、不能过滤的情况

- **画面内嵌广告**：烧录在像素里的跑马灯、水印、条幅。切片本身是正片内容，URL/结构规则无能为力，只能靠播放器遮罩/忽略区域处理。
- **广告伪装成正片目录**：若某站把广告 ts 放在与正片完全相同的目录、并按正常时序插入（无 CUE 标记），URL 与结构规则都无法识别。
- **直播流**：规则同样生效，但直播的分片目录本就可能动态变化，触发条件更严格，命中率低于点播。
- **`advert` 规则从严**：任何含 `advert` 的路径都会命中，包括 `advertisement_free/` 这类命名。实测采集站不会用这种目录名，宁可从严，不做语义判断。

## 七、回归自测

改完规则或 `RULE_CONF` 后跑一遍（不依赖网络，纯构造样本）：

```bash
node tools/ad-filter-selftest.js
```

覆盖 21 个用例：URL 规则正/负例、CUE 区间、DISCONTINUITY 广告块与不误杀、少数派目录剔除与双 CDN 不误杀、相对路径切片识别与不误杀、master playlist / 非 m3u8 / 样本不足三个边界。全部 PASS 才算通过。

打包后另需确认压缩产物同步（`prepare-assets.py` 会用 esbuild 重写 `android/assets-flat/www_ad-rules.js`），可直接对该文件复用同一批断言。

设备端另有一层验证：`bash tools/adb-eval.sh --file <js>` 可在 App 的 WebView 里直接跑上述断言，确认 APK 内的规则与源码一致。

## 八、如何扩展规则

运行时扩展（不用重新打包）：

```js
window.AdFilter.RULES.push({ re: /新广告特征/i, desc: '说明' });
```

永久扩展：编辑 `ad-rules.js` 的 `RULES` 数组；调整结构判定松紧改 `RULE_CONF`：

| 参数 | 默认 | 作用 |
|---|---|---|
| `MIN_SEG` | 20 | 低于此切片数不做结构判断 |
| `DOM_SHARE` | 0.6 | 主流目录占比门槛 |
| `OUTLIER_SHARE` | 0.08 | 少数派目录占比上限 |
| `OUTLIER_MIN` | 2 | 少数派条数下限 |
